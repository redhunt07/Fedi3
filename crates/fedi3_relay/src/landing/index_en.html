Federated social, the account on your device.

Fedi3 is a federated social app whose account, signing keys and encrypted chats stay in a local Rust core on your phone or desktop. ActivityPub keeps you talking to Mastodon and Misskey; a peer-to-peer layer keeps you reachable without a server.

How the Fedi3 core works

Fedi3 is not another hosted instance. It is a client plus a local core you own, with an optional relay for federation and offline delivery.

Local keys

Signing and chat encryption run in the local core. The relay stores ciphertext and public data; it never holds your private keys.

P2P delivery

A libp2p layer carries posts and chat directly between peers. A P2P-only account works without any relay.

Fediverse compatibility

ActivityPub actors, inbox and outbox, HTTP signatures and WebFinger: Mastodon and Misskey see a normal actor.

Encrypted chat and calls

Encrypted 1:1 and group chat with Kyber768-derived keys, audio and video calls over ICE/TURN, screen sharing on desktop.

Open source

AGPL-3.0-only, reproducible release checks and signed relay transparency logs.

Android battery

Background profiles cut idle CPU to about 1% of a core on tested Android devices.

Install Fedi3

You need a client and a way to be reachable. That second part can be this relay, your own relay, or nothing at all if you only use P2P.

Install the client

Download the package for your system from the release page and verify the SHA256 checksum.

Create a local profile

The first run creates the identity on your device. The core starts automatically; there is no separate server process to manage.

Pick a relay

In Settings → Account enter a relay URL and a token of at least 16 characters. On relays that allow self-registration the account is created on first connection; otherwise ask the operator for a token. Skip it for a P2P-only account.

Fedi3 FAQ

Do I need to run a server?

No. A P2P-only account keeps working without a relay. A relay is useful for federation with classic instances and for store-and-forward delivery while your device is offline.

Is it a Mastodon replacement?

It speaks ActivityPub, so it interoperates with Mastodon and Misskey rather than replacing them. The difference is where the account lives: in a local core on your device instead of a hosted instance.

Can the relay read my messages?

Public posts are public by nature. Private chat is encrypted end to end in the client; the relay stores ciphertext and routes it. Attachments in the media backend are not end-to-end encrypted. There is no forward secrecy yet: this limitation is documented.

Which platforms are supported?

Linux (AppImage, Debian/Ubuntu), Windows x64 and Android (arm64-v8a and x86_64). The Flutter project also contains iOS and macOS runners, but no iOS/macOS packages are published yet.

Is it ready for everyone?

It is pre-1.0. The core features work and are tested, but expect breaking changes between minor releases. Release notes list what changed and what is still open.

What does this relay do with my data?

It routes signed ActivityPub traffic, keeps a bounded offline queue, stores media when configured, and publishes a signed transparency snapshot you can pin independently.
